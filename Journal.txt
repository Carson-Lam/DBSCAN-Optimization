Coarse rule: We have multiuple coarse grids. We get the smallest course grid with side >= eps
Fine rule: Not next smaller grid, needs to be largest grid with side <= eps / sqrt(2) bc guarantee
            cares about the diagonal. Guarantee is that "If a fine cell contains ≥ minPts points, 
            every point in that cell is a core point" but only if every pair in the cell
            is within eps, including farthest apart at on the diagonal corners.

Using given list:
        eps = 0.1
        'next smaller than eps'         -> 0.080   diagonal 0.1131  > eps   BREAKS
        'largest level <= eps/sqrt(2)'  -> 0.067   diagonal 0.0948  <= eps  OK

- Hierarchy for MaxRS should still be valid using the same method. Precompute MaxRS for
    a ladder of rectangle sizes. A small dense rectangle stays dense at larger ε,

    vs O(L*n) grid for an index of L size.

Problems:
1. In short, noise too sparse can fill a block past minPts. For full runs, 
early termination only works when noise is sparse. According to the proof, every 
block holding unlabelled points needs to be under minPts. There is a case where a noise-only
block with more than minPts gets every point checked individually.

Causes:
    - The block is much bigger than a ε-neighbourhood. 3x3 block: 3ε × 3ε = 9ε² vs ε-disc: πε² ≈ 3.1ε²
    - A point marked noise still counts towards neighbour's ε-neighborhoods. We can't subtract it
    - The denser the noise, the more blocks pass minPts by chance, leading to that case, and leading   
        to more points getting checked one at a time.

2. When ε sits right above a Hierarchical rung, the coarse grid (smallest grid more than ε) 
is up to 2x too big. For sparse noise that means a lot of individually checked noise points.

Conclusions from problems:
- The full-run speedup only happens when the noise is sparse. Worst case is still same as DBSCAN,
so algorithhm should still be faster. Building the grid can be overhead.
